# 项目说明

## 这是什么

Iris 是供正畸医生在 E看牙网页内使用的本地临床文书助手。它把复诊口述要点或初诊结构化选择转成固定病历表达；生成内容可继续编辑，并由医生审核后填入当前 E看牙病历编辑页。

Iris 不是诊断决策、治疗推荐或自动保存工具。临床判断、最终文字修改和保存均由医生完成。

## 使用者与场景

- 使用者：在 E看牙中书写正畸病历的医生。
- 场景一：复诊时输入或语音记录要点，整理为检查、处置、医嘱；普通复诊可尝试复制既往正畸复诊的诊断与治疗计划。
- 场景二：初诊时在浮窗内勾选/填写模板，生成主诉、现病史、既往史、检查、辅助检查、诊断、治疗计划、处置和医嘱。
- 场景三：粘贴头侧片测量表截图，由本地服务调用 AI 视觉模型（2026-09-04 起，见 DECISIONS D-010）自动填入固定测量项目；医生核对和修改数值。

## 用户流程

1. `Start-Iris.ps1` 启动本地服务，并可调用相邻的 E看牙自动登录项目。
2. 专用 Chrome 打开 E看牙；Manifest V3 content script 注入 Iris 悬浮按钮和 Shadow DOM 面板。
3. 医生选择复诊或初诊。
4. 复诊：浏览器端把要点交给本地服务；服务先检查保持器固定模板，随后优先调用可选 AI，失败或未配置时使用本地规则。
5. 初诊：浏览器端用本地表单逻辑直接组成记录；头侧片截图经本地服务调用 Windows OCR。
6. 医生在 Iris 内检查/编辑生成字段。
7. 点击“填入 E看牙”后，扩展在当前页面寻找相应文本框并写入；不自动保存。

## 已实现的核心功能

### 复诊

- 固定默认基础：主诉“矫正复诊”、现病史“矫正中”、既往史与默认医嘱由扩展逻辑处理。
- 本地规则覆盖牙列、咬合、龋坏/牙周、托槽/颊管/附件问题、弓丝、牵引、弹力链、隐形牙套、支抗钉等常见表达。
- 牵引保留位置和限定词；支抗钉保留牙位或解剖位置及型号。
- 保持器复查走完整固定模板，跳过 AI 以及既往诊断/治疗计划复制。
- 普通复诊填入时，扩展会在右侧历史病历面板中向前查找符合正畸特征的病历，复制诊断和治疗计划。

### 初诊

- 主诉多选、年龄/患者类型相关现病史、既往史的“否认/具体内容”联动。
- 面部、TMJ、口内、牙弓/牙列、少见牙位情况、头侧片、诊断、治疗方案、风险、处置和医嘱。
- TMJ、牙位情况与治疗方案使用可展开的可编辑条目。
- OCR 固定录入 SNA、SNB、ANB、Wits、MP-SN、FMA、U1-SN、L1-MP（IMPA）；当前对 ANB 和 Wits 有本地负号/小数点补偿。

### 页面交互与安全

- 悬浮窗位置保存在 `chrome.storage.local`。
- API 密钥不在扩展中；设置脚本写入 Windows 用户环境变量。
- 不确定 E看牙字段时，填入逻辑返回失败或部分成功提示，而不是盲目填充。
- 扩展当前 UI 不调用服务端的保存确认接口；医生在 E看牙网页自行保存。

## 当前完成度

复诊规则、初诊模板和 E看牙填入已可用，但没有自动化回归测试。项目强依赖 E看牙现有页面结构和真实临床核对，属于持续迭代中的本地工具，而非可独立部署的通用产品。

## 已知边界

- 历史病历抓取和字段定位依赖 E看牙 DOM、右侧历史栏位置与文本；网页改版可导致失败。
- Windows OCR 已不再用于头侧片识别（2026-09-04 起改用 AI 视觉模型，见 D-010）；其负数/小数点不稳定的旧问题及局部补偿仅存于保留代码中。
- 复诊自然语言本地规则覆盖常见表述而非完整语义理解；AI 可改善部分输入，但也受外部模型可用性影响。
- 初诊表单为浏览器端模板，不调用 AI；其临床措辞和可选项需持续由医生确认。

## 未来方向（不是当前承诺）

- 将代表性、脱敏输入固化为规则/OCR 回归测试。
- 为 E看牙 DOM 变化建立更明确的兼容性检查和可读诊断。
- 将临床规则按主题拆分为可审查的数据或模块，但必须先保留当前行为并获得明确授权。
- 如需要多机使用，建立安装说明和不含登录态的配置模板。
