## 已知问题

- Windows OCR 可能漏识别负号、小数点或彩色箭头；ANB/Wits 已有特定布局补偿，但仍需人工核对。
- E看牙输入框和右侧历史栏定位是启发式逻辑，可能随网页布局、滚动容器或加载状态变化而失败。
- AI 响应是外部依赖；本地规则会回退，但未覆盖每种口述表达。
- 当前没有 Git 历史，因此早期修改的动机和责任人无法从项目确认。

## 技术债

- `iris_server.py` 同时承载 HTTP、规则、AI、OCR 和 CDP；`content.js` 同时承载 UI、表单、E看牙 DOM 和历史抓取。
- 临床规则主要是代码内正则和条件分支，缺少可执行测试案例。
- 服务端保留一个可在确认后尝试点击保存的 CDP 接口，与“UI 不自动保存”的产品边界需要持续明确区隔。
