# 设计决策与约束

## D-001：本地优先，扩展不保存 AI 密钥

**现状**：Chrome 扩展只调用 `127.0.0.1:9323`；`iris_server.py` 从 Windows 用户环境变量读取 API 密钥。

**原因**：代码和设置脚本明确如此实现。API 密钥不应进入扩展包或 `chrome.storage`。

**约束**：不要把密钥写入 `manifest.json`、`content.js`、`background.js`、`terms.json`、日志或 Git。

## D-002：确定性本地规则是复诊安全网

**现状**：服务优先尝试 AI，再使用本地规则稳定化；AI 未配置或异常时使用 `local_generate`。保持器复查直接走固定本地模板。

**原因**：可从代码确认；具体历史原因无法从当前项目确认。

**约束**：新 AI 功能不能删除本地回退、固定模板和医生审核步骤。

## D-003：保持器复查不能复用普通复诊逻辑

**现状**：`retainer_followup_record` 返回完整固定字段，`/api/generate` 在 AI 调用前识别。

**约束**：不得追加普通复诊默认医嘱，不得从旧病历复制诊断或治疗计划。

## D-004：初诊使用本地结构化模板

**现状**：初诊由 `content.js` 的 `buildInitialRecord` 构造，头侧片 OCR 仅提供测量值。

**原因**：可从代码确认；表单临床条目的历史选择原因无法从当前项目确认。

**约束**：新增字段时同时检查输出、重置、填入映射、样式和编辑性。

## D-005：E看牙写入必须保守，保存必须人工完成

**现状**：扩展直接定位输入框并写值；页面不确定时返回失败/部分成功。扩展未调用服务端 `/api/confirm-save`。

**约束**：不要增加自动保存或弱化字段不确定时的停止策略。服务端仍有保存确认脚本属于高风险历史接口，除非用户明确授权和完成安全审查，否则不要接入 UI。

## D-006：普通复诊从右侧历史栏复制诊断/治疗计划

**现状**：内容脚本通过文本、日期、可点击目标和滚动来找历史正畸病历。

**原因**：当前代码实现可确认；E看牙 DOM 的原始设计原因无法从项目确认。

**约束**：该功能依赖外站 UI。任何改动都必须在真实编辑页验证，并保留“找不到则提示手工补充”的行为。

## D-007：Chrome 调试端口是本机 E看牙桥梁

**现状**：E看牙自动登录和 Iris 使用 `config.json` 中的调试端口（当前本机可见为 9223）；服务端可经 CDP 找到登录后的网页。

**约束**：不把端口暴露到局域网；不要删除专用 Chrome profile；不要误杀日常 Chrome。

## D-008：OCR 结果均需医生核对

**现状**：头侧片识别自 2026-09-04 起仅调用 AI 视觉模型（见 D-010），**不再回退本机 Windows OCR**（其负号、小数点不稳定且会静默填入错误数值）。`local_windows_ocr`/`recover_ceph_value` 保留为历史代码，不再被任何路由调用。

**约束**：不要把识别数值视作临床事实或隐藏输入框。新截图版式应先验证；AI 识别结果同样需医生核对。

## D-009：UI 使用 Shadow DOM 和本地存储位置

**现状**：扩展将样式和面板置于 Shadow DOM，并将浮窗/按钮位置写入 `chrome.storage.local`。

**约束**：不要轻易改为全局 CSS 或网页 DOM 污染；布局调整要同时测试初诊和复诊面板的定位。

## D-010：头侧片识别使用 AI 视觉模型（2026-09-04 医生授权，仅视觉）

**现状**：`/api/ceph-ocr` 仅调用视觉模型——模型取 `IRIS_CEPH_MODEL`（=`deepseek-v4-flash-vision-exp`），未设时回退 `IRIS_AI_MODEL`；失败自动重试 3 次，全部失败则显式报错给医生。**不再回退 Windows OCR**（2026-09-04 医生实测后要求，因其负号识别不可靠且会静默填入错误数值）。复诊文字 AI 仍用 `IRIS_AI_MODEL`，两者互不影响。`Start-Iris.ps1` 已将 `IRIS_CEPH_MODEL` 纳入用户环境导入列表。

**原因**：视觉模型可精确保留负号与小数（真实截图实测 Wits -2.6 正确）；Windows OCR 在该版式上丢失负号。

**约束**：头侧片截图（患者临床数据）会离开本机发送给 AI 提供商——这是对旧"图片不出本机"原则的有意反转，医生已明确授权。识别结果仍需医生核对。若日后撤换：删除用户环境变量 `IRIS_CEPH_MODEL` 并回退本段。`local_windows_ocr`/`recover_ceph_value` 保留为历史能力，不再被任何路由调用。

## D-011：填入成功后立即收起悬浮窗，但不清空草稿

**现状**：`chrome-extension/content.js` 的 `refs.fill` 点击处理在 `fillEkanya()` 返回 `result.ok` 后调用 `closePanelAfterFill()` 移除 `.open` 类，窗口立即收起。**只收起、不重置**——`state.record`、复诊要点与已填字段全部保留；医生点 Iris 悬浮钮即可重新展开回看、编辑或再次填入。填入失败或抛错时不收起，保留错误状态供原地修正。原「完成治疗」触发的 `resetIrisDraft({closePanel:true})` 保留，负责跨患者清空草稿。

**原因**：此前悬浮窗只在点击「完成治疗」后才关闭，每例复诊多一次点按。医生要求填入完成即收起以减少操作（2026-09-06）。

**约束**：不要把"收起"与"清空草稿"合并。收起是 UI 状态、清空是数据状态，二者必须分离——自动清空会导致医生无法在下一患者开始前核对刚填的病历。后续若要新增自动收起触发点，同样只移除 `.open` 类、不调用 `resetIrisDraft`。
