# 设计决策与约束

## D-001：本地优先，扩展不保存 AI 密钥

**现状**：Chrome 扩展只调用 `127.0.0.1:9323`；`iris_server.py` 从 Windows 用户环境变量读取 API 密钥。

**原因**：代码和设置脚本明确如此实现。API 密钥不应进入扩展包或 `chrome.storage`。

**约束**：不要把密钥写入 `manifest.json`、`content.js`、`background.js`、`terms.json`、日志或 Git。

## D-002：确定性本地规则是复诊安全网

**现状**：服务优先尝试 AI，再使用本地规则稳定化；AI 未配置或异常时使用 `local_generate`。保持器复查直接走固定本地模板。

**原因**：可从代码确认；具体历史原因无法从当前项目确认。

**约束**：新 AI 功能不能删除本地回退、固定模板和医生审核步骤。

## D-003：保持器复查不能复用普通复诊逻辑

**现状**：`retainer_followup_record` 返回完整固定字段，`/api/generate` 在 AI 调用前识别。

**约束**：不得追加普通复诊默认医嘱，不得从旧病历复制诊断或治疗计划。

## D-004：初诊使用本地结构化模板

**现状**：初诊由 `content.js` 的 `buildInitialRecord` 构造，头侧片 OCR 仅提供测量值。

**原因**：可从代码确认；表单临床条目的历史选择原因无法从当前项目确认。

**约束**：新增字段时同时检查输出、重置、填入映射、样式和编辑性。

## D-005：E看牙写入必须保守，保存必须人工完成

**现状**：扩展直接定位输入框并写值；页面不确定时返回失败/部分成功。扩展未调用服务端 `/api/confirm-save`。

**约束**：不要增加自动保存或弱化字段不确定时的停止策略。服务端仍有保存确认脚本属于高风险历史接口，除非用户明确授权和完成安全审查，否则不要接入 UI。

## D-006：普通复诊从右侧历史栏复制诊断/治疗计划

**现状**：内容脚本通过文本、日期、可点击目标和滚动来找历史正畸病历。

**原因**：当前代码实现可确认；E看牙 DOM 的原始设计原因无法从项目确认。

**约束**：该功能依赖外站 UI。任何改动都必须在真实编辑页验证，并保留“找不到则提示手工补充”的行为。

## D-007：Chrome 调试端口是本机 E看牙桥梁

**现状**：E看牙自动登录和 Iris 使用 `config.json` 中的调试端口（当前本机可见为 9223）；服务端可经 CDP 找到登录后的网页。

**约束**：不把端口暴露到局域网；不要删除专用 Chrome profile；不要误杀日常 Chrome。

## D-008：OCR 结果均需医生核对

**现状**：Windows OCR 的负号、小数点会不稳定；当前对 ANB/Wits 在特定截图布局使用局部补偿。

**约束**：不要把 OCR 数值视作临床事实或隐藏输入框。新截图版式应先用脱敏样例验证。

## D-009：UI 使用 Shadow DOM 和本地存储位置

**现状**：扩展将样式和面板置于 Shadow DOM，并将浮窗/按钮位置写入 `chrome.storage.local`。

**约束**：不要轻易改为全局 CSS 或网页 DOM 污染；布局调整要同时测试初诊和复诊面板的定位。
